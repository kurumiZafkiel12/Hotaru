# Hotaru 0.4.1 · Windows 安装预览

在 v0.4 基础上补齐日常代理功能。下载 `Hotaru-0.4.1-windows-x64-setup.exe`，关闭旧 Hotaru 后覆盖安装，订阅和布局保留。首次使用：配置 → 下载或粘贴订阅 → 节点 → 启动代理 → 系统代理。

- **配置 / 节点分离**：默认保留订阅自身分流，支持仅含 proxy-providers 的配置；运行后合并内核代理与 Provider 节点，不限制显示数量。
- **订阅**：多个订阅、HTTPS 链接保存、手动 / 定时更新、来源提供的剩余流量和到期时间。每个配置可设 0–720 小时更新间隔，默认 24 小时；应用运行期间执行。更新先通过内核验证，失败保留旧配置；运行中更新在下次启动内核生效。
- **节点**：select / url-test / fallback / load-balance 原生策略组、显式手动组切换、节点搜索、真连接延迟、TCP 握手延迟、最多四并发全组测试及延迟排序。Provider 节点测速使用对应 Provider API；未暴露服务器的节点不伪造 TCP 数值。
- **分流**：规则 / 全局 / 直连三态；保留 rule-providers，并支持刷新远程节点集、规则集。
- **覆写**：原订阅 → Merge → Script。Merge 递归合并字典、整体替换数组；用户脚本 main(config) 在独立 Node 进程执行，设有时限与内存限制。仅填写你信任的脚本，运行环境不是恶意代码安全沙箱。订阅更新不会覆盖这些设置。
- **连接与日志**：内核 API 实际连接快照、断开连接、实时流量和本机最近 200 条日志。
- **Windows**：独立代理守护进程在 UI / 内核退出时恢复仍由 Hotaru 占用的系统代理；已有外部修改会保留。正常退出先恢复代理再停止内核。关窗隐藏到托盘，灰 / 绿区分状态，托盘右键可退出；支持静默开机自启。
- **服务基础**：可选 SCM 服务承载固定的内置 Mihomo，安装 / 卸载各需管理员授权；运行不重复 UAC。服务以 LocalService 运行，安装文件与服务数据分开设置 ACL，管道仅允许安装时的用户 SID，客户端核对服务 PID，断开租约自动停止内核。**TUN 尚未开放**，下一阶段需要单独完成具有网络管理权限的接口审查与适配；当前服务不能被描述为已经具备免 UAC 的 TUN。
- **更新**：启动及每六小时自动检查 GitHub 发布，点击下载安装后校验 SHA256、清理代理并退出覆盖安装。不会在连接中途自动强制安装。

限制：Windows x64 预览尚未代码签名；Android/Linux、可视化多跳编辑、IP 质量检测和下载带宽测试继续开发。原配置中已有 dialer-proxy 保留。节点 URI 转换支持原有八类协议，其他 Mihomo 原生协议请使用完整 YAML/JSON，无法保证所有第三方私有 URI 参数。首次 Provider / Geo 数据加载依赖网络。服务不支持同时由多个 Windows 账户占用；本机 file Provider 在 LocalService 下可能没有访问权限，此时使用普通模式。凭据保存在当前用户目录；卸载保留配置。断电、强制终止守护进程本身属于下次启动检查遗留备份的恢复范围。

构建只有在分析、单元测试、真实代理链路、Provider API、Script、隔离崩溃恢复、服务及安装升级验证全部通过后才发布。
