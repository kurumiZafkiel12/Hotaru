# 开发与验收计划

每阶段执行：实现 → 自动测试 → 人工检查 → 记录限制 → 提交。失败不推进；计划中的功能不能显示为已实现。

## M0：工程和交互原型（当前）
- 独立、可运行的 Vite 原型，布局本地保存。
- 组件增加、移除、拖动与键盘按钮排序。
- 工具箱只展示未接入状态，不生成虚假测速或 IP 数据。
- 代理链草稿验证；不代表运行配置或协议兼容性检查。
- 验收：模型测试、浏览器交互测试、窄屏布局、生产构建。

## M1：正式跨平台工程
- 首选评估 Flutter，覆盖 Windows、Android、Linux；原型仅用于验证产品交互，不视为正式桌面技术栈。
- 安装并固定 Flutter/Go 与 Windows C++ 工具链；运行 doctor，构建空壳应用。
- UI、领域数据、内核适配、系统集成分层；内核操作不能直接写在组件里。
- 验收：干净 Windows 环境构建与启动；测试平台适配接口。

## M2：节点与订阅
- 实现支持列表明确的 URI 解析，覆盖编码、IPv6、空字段和错误输入。
- 两种模式：提取节点；保留完整 Mihomo 配置并显式展示客户端覆盖字段。
- 订阅原始内容与用户覆写分开保存；使用稳定引用，名称冲突不能静默覆盖。
- 更新先下载、校验、生成候选，内核验证通过后原子替换；失败回滚。
- 禁止默认第三方订阅转换；敏感链接和凭据不进入日志。
- 验收：恶意/损坏配置、更新断网、重复名称、节点消失、取消操作。

## M3：Mihomo 接入
- 固定内核版本、来源、校验和与许可证；配置检查后启动。
- 控制接口仅绑定回环地址并认证；实现启动、健康检查、停止、崩溃处理。
- 连接状态以实际内核状态为准；实时连接与流量通过适配层订阅。
- 验收：端口冲突、内核缺失、无效配置、进程退出与资源释放。

## M4：Windows 系统集成
- 系统代理变更前记录原值；退出恢复时避免覆盖用户或其他软件后续修改。
- TUN 与服务安装采用最小权限；UI 不常驻管理员权限。
- 托盘、单实例、开机启动、休眠恢复、网络切换。
- 验收：标准用户、权限拒绝、异常退出、卸载、代理恢复。

## M5：分流、多跳与工具箱
- 可视化生成 dialer-proxy 引用；循环检测包含策略组依赖，不仅是重复节点。
- 不同链路隔离生成节点，校验 TCP/UDP 与协议组合。
- 指定节点独立检测，不切换全局用户连接；整链真实测量。
- 延迟与带宽分开；下载测速有超时、流量上限、取消与并发控制。
- 免费 IP 来源显示时间、来源、配额失败与未知值；不承诺统一纯净度。
- 验收：受控节点环境下单跳/三跳、故障切换、取消后无残留连接。

## M6：发布
- 在 CI 构建 Windows x64，产物附版本、SHA256、第三方许可与已知问题。
- 全新 Windows 10/11 虚拟机验证安装、运行、升级与卸载。
- 发布预览 Release；未签名情况如实说明，不声称通过签名验证。
- 通过真实代理验收前不发布为可用代理客户端。

## M7：Android、Linux
- Android VpnService、应用分流、前台服务与电池策略单独实现并实机测试。
- Linux 权限、桌面托盘和 DNS/路由恢复单独验收。
