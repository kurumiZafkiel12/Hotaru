# Configuration import

`ClashSubscriptionImporter` prepares provider declarations, resolves their payloads through an application-owned callback, expands group membership, then delegates protocol/rule conversion to `ClashProfileImporter`. Parsing and expansion run in isolates. No kernel or filesystem operation is performed by the importer.

The resolver receives the original URL, headers, requested outbound, relative file/cache path, refresh interval, timeout and byte limit. It must authorize file access, honor the requested route, and cancel/close its transport on timeout. An importer timeout stops scheduling additional providers; it cannot cancel a callback's underlying I/O. Automatic scheduling and persistent caching belong to the subscription owner, not this parser.

Supported provider inputs are HTTP, explicitly resolved relative files, and inline payloads. Remote/file payloads must contain only a `proxies` list. Empty/ambiguous providers and unconverted settings produce structured issues; resolution failure returns no partial profile. Provider health checks and moved cache paths are reported as conversion warnings. Consumers must present warnings and validate the resulting IR with the target builder before applying it.

Limits are 64 providers, 16 MiB per input/payload, 32 MiB of resolved payloads, 100,000 nodes and 250,000 expanded membership references. The callback must enforce its payload byte limit while reading; the importer rechecks returned data before parsing. An immutable plan exposes refresh metadata without granting filesystem or routing authority.

## DNS conversion subset

Enabled Clash DNS can specify one upstream (UDP, TCP, TLS or HTTPS), one optional bootstrap resolver and one optional resolver for proxy hostnames. Hostname-based DNS endpoints require explicit bootstrap. `system` selects sing-box's local resolver. Endpoint fragments can name a validated outbound; recursive DNS/outbound dependencies are rejected before applying a profile. DNS queries with URL options, parallel upstream lists, fallback policies, fake-IP, DNS rule policies and forced HTTP/3 remain conversion errors. Disabled DNS is not applied and unused settings are reported.

Hosts and system-hosts behavior is not yet migrated and is reported as a warning when enabled (including Clash defaults); consumers must show this before application. Imported listener addresses never grant binding authority. `CoreListenerSpec.dnsPort` creates an optional loopback UDP/TCP DNS inbound, while `CoreTunSpec.hijackDns` explicitly enables port-53 interception on the owned TUN only. Both require a DNS specification and neither changes OS DNS settings. TUN interception defaults off. DNS configuration changes require rebuilding the owned session.

Tests validate generated JSON against pinned sing-box 1.14.4 and use independent loopback UDP/TCP upstream receipts to verify resolution, caching and the IPv6 query policy. TCP connection-reuse probes are counted separately from additional business queries. The opt-in Windows native test also verifies an IPv4 UDP DNS question through the real Helper-owned TUN against an independent upstream receipt and response address, followed by lifecycle and network-baseline cleanup checks. TLS/HTTPS wire behavior, full default-route takeover and IPv6 TUN DNS are not yet acceptance-tested.

## Rule-provider conversion subset

`ClashSubscriptionImporter.resolveRules` supplies an independent application-owned resolver for HTTP and authorized relative-file rule providers. Inline providers require no I/O. YAML payload lists and plain-text lists support `domain`, `ipcidr`, and DOMAIN/DOMAIN-SUFFIX/DOMAIN-KEYWORD/IP-CIDR/IP-CIDR6 classical entries. IP entries require `no-resolve` at the RULE-SET reference or the classical entry. Exact domains stay exact; `+.example.com` includes the apex and its subdomains. Other wildcard and suffix-only forms, MRS, GeoIP/logical entries, nested actions, unknown modifiers and unsupported settings fail conversion. They are not silently flattened into approximate routes.

Expansion retains profile order, target/reject actions and MATCH boundaries, including empty sets. Any resolution or member error yields no replacement profile. Limits are 64 declarations, 16 MiB per remote payload, 32 MiB for aggregate remote payloads and the input document, and 250,000 stored/expanded rule entries. Payload parsing and expansion are isolated from the UI. Resolver timeout stops new scheduling; callbacks must enforce byte limits while reading, authorize files, honor requested routing and cancel their own I/O. Refresh intervals are metadata; scheduling and persistent cache integration remain unfinished.

## IP matching and DNS semantics

IP-CIDR/IP-CIDR6 rules and `ipcidr`/classical sets support explicit `no-resolve`. The owned IR records this flag; builder validation rejects implicit resolving IP rules and rejects this flag on other rule kinds. A domain skips these IP rules and continues to later rules; a literal IPv4/IPv6 destination is matched against its prefix. Offline preview applies the same distinction without sending DNS requests. An IP-only set requires the reference flag even when empty, because the source engine can otherwise attempt resolution for an empty set.

Implicit resolution is not converted yet. Mihomo attempts one address and continues routing after DNS failure, whereas an explicit sing-box resolve action can match multiple answers and terminates the request on lookup failure. Generating only `ip_cidr`, or inserting an unconditional resolve action, would silently change behavior; such imports now report `ip_rule_resolution_not_migrated`. Even direct IR callers must declare `noResolve` for IP rules. Prefix syntax and family bounds are checked consistently during import, generation and preview; scoped/mapped IPv6 prefixes and ambiguous prefix forms are rejected pending established cross-engine semantics. This is a compatibility correction to the initial prototype, which accepted unqualified IP rules without implementing their DNS behavior.

## Preparation and conversion review

`SingBoxConfigPreparer` takes an application-owned import callback and immutable listener settings. Import errors, builder validation and complete bootstrap-envelope size checks finish before any Helper session is created. Heavy issue processing, JSON generation and encoding run in data-only isolates; importer callbacks and their native resources stay with the caller. Results distinguish a reviewable candidate, an invalid configuration and a superseded preparation. New preparations/cancel invalidate older reviews without mutating an already accepted running snapshot; cancellation does not cancel the callback's own I/O.

A candidate exposes structured conversion warnings and the encoded size for presentation. If it has warnings, the UI must obtain an acknowledgment from its explicit confirmation action and pass that candidate-bound token to `approve`. A token from another candidate is rejected even when warning counts or codes are the same. The privileged Helper composition accepts only `AcceptedSingBoxConfig`; its pipe consumes the already prepared, immutable bootstrap. PID/session/peer checks still run before credentials are transmitted.

The 16 MiB limit covers UTF-8 JSON plus the protocol envelope, excluding the transport's length prefix. Chunked encoding stops at the limit rather than first allocating arbitrarily large repeated JSON. Rule-set expansion has a separate 16 MiB text budget before joining repeated targets, in addition to its rule-count bounds. The preparation result contains no raw exception text or configuration dump.

Preparation/approval does not apply, reload, stop or replace a running session. It does not establish complete upstream engine validation, port availability or successful startup. Callers must not stop the existing core merely to prepare a replacement. Ordinary GUI application and its localized review screen remain to be integrated.


## Runtime activation and recovery

The Windows Helper composition accepts a reviewed configuration through `SingBoxDesktopCore.applyConfiguration`. Its launch plan binds bootstrap, pipe, listeners and controller credentials together. The existing `DesktopCoreLifecycle` serializes replacement with start/stop/restart/close, confirms the old lease has exited, and commits a plan only after the new process and its controller have passed ownership checks. Session-scoped API clients are recreated with the active plan's endpoint and secret.

If activation fails while replacing a running configuration, the same owner attempts to restore the last committed plan after confirming failed-process cleanup. A successful recovery leaves the core running and rejects the apply request with `configuration_rejected_previous_restored`; the rejected configuration is not committed. A failed or unconfirmed cleanup blocks recovery instead of starting a second core. Recovery failure leaves an explicit failed state and permits an explicit retry. Replacement cuts existing connections; this is a controlled restart, not seamless hot reload.

Stop/close preempt activation and recovery. A later explicit start/restart uses the last committed plan and supersedes a pending replacement; a newer apply uses its new plan. Requests for the same plan may coalesce, but different plans do not. Superseded late processes are cleaned without publishing a running session. Applying from idle starts the requested plan, but a failure does not unexpectedly start a previously stopped plan. No GUI or provider owns a separate recovery loop.

## Previewing the committed session

An accepted configuration retains the immutable IR that produced its bootstrap. Candidate summaries expose node/rule counts without decoding the compiled JSON. `SingBoxDesktopCore.previewRoute` uses that committed IR and the running session's actual selector values, rather than pending UI settings or subscription defaults. It rejects results when the session/configuration changes; relevant selectors are read again before returning so a changed selection cannot be presented as current.

Preview evaluates domain/literal rules in an isolate and only reads the local controller. It does not resolve or connect to the target, start a stopped core, or change a selector. A missing running profile, incomplete selection or unsupported rule remains explicit. This query is ready for the Windows facade; the ordinary GUI entry is not wired yet.

## Node detours

Clash `dialer-proxy` is retained as a node detour and generated as sing-box `detour`. References and cycles are checked across nodes and selectors together. Empty direct outbound detours are rejected before startup, as the pinned engine rejects them too. DNS dependency checks distinguish explicit client resolution from hostname forwarding through a detour; a remotely resolved server must not invent a local resolver cycle.

Preview keeps policy selection order in `chain`, exposes entry-to-exit node order in `hops`, and records all used selections, including detour groups, for session verification. Controlled tests require independent CONNECT receipts at the relay and exit plus the origin payload, through both the pinned CLI and Hotaru's embedded host. The upstream connection API omits the relay in this tested case: its raw `chains` is not by itself a complete physical path. In particular, historical selections of a detour group cannot be reconstructed from its current selection and must not be presented as observed connection history.

## HTTP through a specified outbound

An optional authenticated HTTP listener binds only to loopback. The compiler generates a username per known node/group and inbound-scoped `auth_user` routes before subscription rules, followed by a reject rule for unmatched probe traffic. Its port must be distinct from the mixed, controller and DNS listeners. A per-configuration random secret is required; it travels inside the existing private bootstrap, not command arguments. No second engine or mutable global selector is used.

`CoreOutboundHttp.withOutboundClient` scopes a Dart HTTP client to that listener and one outbound. The callback must finish consuming its responses before returning and must not replace the client's proxy configuration or retain the client. Completion, exceptions, timeout and session invalidation close the client; stale results are rejected. Unknown nodes and absent capabilities fail without falling back to a direct route. Credentials are registered for the exact loopback proxy before requests because the pinned engine's 407 challenge is not accepted by Dart's authentication parser. Normal origin TLS checks remain enabled. Windows verifies both controller and probe listener ownership before authenticating the session.

The wire test uses simultaneous HTTP and HTTPS requests, two independent CONNECT proxies, origin bodies, unchanged selector state and rejected unauthenticated traffic. The embedded host must acknowledge clean shutdown. A disposable Windows Helper test also queries through the restored configuration's probe listener after failed activation. These checks establish transport capability, not completion of ordinary GUI node speed/IP probe integration.

## Outbound modes

Generated configurations explicitly implement rule/global/direct routing with `clash_mode` rules. Changing the controller's mode alone does not change sing-box routes. A generated global selector defaults to the profile's final outbound and includes its existing nodes/groups; a dedicated direct outbound bypasses profile rules. Generated names use deterministic collision-free suffixes and never rename subscription nodes. DNS hijack and authenticated per-node probe rules precede mode overrides. The controller starts in rule mode; preserving a user-selected mode across apply/restart belongs to the application facade.

`CoreRoutingModes` reads the actual mode and patches it with verified readback. Session adapters reject acknowledgements from replaced processes. Preview reads the mode with the same committed profile/session as its selector snapshot and rechecks it before returning; global/direct previews bypass profile rules. The real-engine test requires separate A/B proxy receipts, direct origin access with no proxy receipts, and a pinned A probe even while direct mode is active. These checks do not claim the ordinary UI facade is already cut over.

## UI bridge and scoped speed-test clients

`SingBoxUiHandler` implements the existing UI handler boundary over one already prepared `SingBoxDesktopCore`. Lifecycle methods delegate to its owner. Group conversion hides the upstream API's synthetic, unwritable GLOBAL entry when the subscription does not own that tag; the actual generated global selector remains available. Connection rows preserve observed creation time, process path and raw chain, without treating a PID as an account UID or inventing missing relay hops. Mapping runs in an isolate and rejects replaced sessions. Unimplemented legacy methods return `sing_box_method_unavailable`; they never delegate to Mihomo. Ordinary application construction is not switched until the remaining methods and import/apply integration are ready.

`CoreOutboundHttpClients` resolves a clicked group to a leaf once and scopes a client factory to that immutable selection. All clients use the owned authenticated probe listener. Success, errors, timeout and session replacement close the entire set; a retained factory cannot create clients after its scope or session ends. The speed-test runner accepts this factory without changing its proxy binding, so selection, latency, download and upload phases can create separate clients while retaining one node. The node-card branch uses the scope's chain and accepts its final result only after the session guard returns. It does not mutate global selection or use unrelated route revisions to invalidate a pinned test. The legacy branch remains for the unchanged Android/Mihomo entry until migration.

Tests exercise the existing CoreController group/connection model paths, card cancellation/disposal, terminal factories, and real HTTP/HTTPS proxy receipts while a group changes after the factory was pinned. Windows Helper verification separately requires `node_http_factory_recovered_configuration` after failed activation/recovery and a rejected retained factory after restart. These checks do not by themselves establish full ordinary-GUI cutover.

## UI selections and route notifications

`SingBoxUiRoutes` serializes policy reads, node selection and mode writes over the existing session adapter. A successful response is acknowledged only after the requested selection/mode is read back in the same committed profile and process. Each observed replacement session/profile gets a new UI epoch. A route version changes only when actual mode/selector state changes; API object ordering does not count. Policy sorting and digest computation run in a data-only isolate.

The existing RouteTracker aggregates UI watchers. While watched, this bridge polls automatic selections; detach immediately stops polling and supersedes a watch still awaiting its first response. Lifecycle observation cancels timers outside a running session. Reads never start a stopped process. Close is terminal, stops observation and drains queued work after the core is closed. Crash forwarding carries a stable failure code and unsubscribes at terminal close.

The old `forSpeedTest` mutation cannot represent the authenticated client-factory scope and is explicitly rejected by this handler. The node-card capability branch uses scoped clients instead. The normal application constructor and remaining legacy method parity are still pending; this route bridge does not by itself switch the released application to sing-box.

## YAML document normalization

All Clash profile/provider/rule-payload YAML and the existing custom-profile import share one bounded decoder. Standard unquoted merge keys follow first-map precedence, with explicit fields winning regardless of position. Quoted `<<` remains data; invalid merge shapes and alias cycles are rejected instead of silently discarded. Alias expansion has independent value, weighted byte and depth budgets (2,000,000 values, 64 MiB and 128 levels), in addition to the 16 MiB UTF-8 input bound. These are decoding budgets, not a total-process heap guarantee. Production callers run this work in their existing data isolates.

Reality `short-id` numeric-looking hex literals retain their source spelling, including leading zeroes; unrelated numeric scalars keep their types. Numeric protocol settings can accept decimal strings without coercing arbitrary scalar values. Top-level `x-` extension/template fields generate review warnings while their inherited node fields remain effective; other unsupported configuration fields retain their existing error behavior. A dry check against the pinned engine validates inherited HTTP nodes and a Reality node with an unquoted `0123` short ID, without starting listeners or claiming remote-node connectivity.

## Application profile document bridge

`CoreProfileDocuments` reads original profile files, hashes their original bytes, returns lightweight summaries/node names, and builds overlay text in data-only isolates. Input streams and encoded output are each limited to 16 MiB; the shared YAML decoder also bounds expansion. Reads and merges never rewrite the source, start a core, resolve providers or change proxy settings. Source nodes/groups/sub-rules take precedence when present, and overlay rules precede source rules. Missing source sections retain the overlay.

`SingBoxUiHandler` exposes these operations to the existing controller. An explicit text-builder capability keeps in-process text separate from the legacy RPC spill-file contract; legacy path validation remains in place. Native Dart `rules` and old RPC `rule` responses both survive controller normalization. These document operations are not sing-box compatibility validation or approval to activate a profile. Encrypted inputs remain explicit errors pending decryption support; complete application import/apply wiring is still unfinished.

## HTTP latency targets

URL-test groups accept validated HTTP and HTTPS targets. Manual HTTPS delay retains the pinned native API behavior. The pinned Clash-compatible delay API silently replaces HTTP URLs with its default HTTPS target, so manual HTTP delay uses the owned, authenticated scoped node client instead. It sends HEAD to the original URL, does not follow redirects, measures through response headers, and closes the client on completion, failure or timeout. Missing scoped capability is an error; there is no direct or default-target fallback. This response timing does not establish service unlock, bandwidth or TLS security. Manual HTTP samples do not update the engine's URL-test history.

Controlled native tests require an additional receipt at the requested proxy and original HTTP origin, an unchanged other proxy and selector, and no request to a redirect destination. They do not access public test targets or change host network settings.

## Sharing-link input

`CoreShareLinks` parses plain URI lists or one whole base64/base64url subscription, with per-input expansion preserved by `decodeMany`. HTTP/HTTPS proxies, SOCKS5, SIP002/legacy Shadowsocks, VMess JSON links, VLESS TCP/WebSocket/gRPC/Reality, Trojan, Hysteria2 and TUIC v5 have bounded decoding paths. Credentials and URI fragments are decoded once, numeric-looking Reality short IDs remain strings, and explicit zero ports are rejected rather than replaced by a scheme default. TLS options, transport options and query parameters are checked; unsupported options (including Shadowsocks plugins, certificate pins and unsupported transports) reject the input instead of being dropped. Any malformed member prevents a partial node list. Diagnostics contain stable codes and indexes, not source URIs or credentials.

The input limit is 16 MiB UTF-8, with 100,000 lines/inputs and 64 KiB per URI. Parsing and import assembly run off the UI isolate. `import` adds a collision-free selector and explicit MATCH for rule-free link lists; decoding alone does not validate compatibility or apply a configuration. Semantic protocol validation remains with the shared importer/builder. `SingBoxUiHandler` exposes Dart decoding and bounded file conversion through the existing controller contract; unsupported legacy encoder/decrypt/validation calls remain explicit errors. The regular application backend is not switched by this input feature.

Pinned-engine checks cover all protocol fixture configurations; the controlled HTTP/HTTPS receipt test now builds its actual proxy nodes from decoded sharing links. These checks do not establish public service interoperability for every protocol.

## UI traffic sampling

`SingBoxUiTraffic` serializes existing-controller speed, total and display-reset requests over private native telemetry. Speeds use byte differences and a monotonic local clock; a total read does not consume the speed window. First samples establish a baseline, samples in one clock tick retain their bytes for the next interval, and same-session counter regressions fail. Replaced sessions/configurations discard old rates and offsets; stale in-flight data and calls after terminal close are rejected.

Display reset captures a local offset and rate baseline. It never resets the kernel counters used by the durable per-profile recorder. Counter-to-rate arithmetic converts before multiplication to avoid integer overflow. The controller observes failures of its fire-and-forget reset call instead of letting an asynchronous error escape.

These are complete unfiltered kernel totals, not a sum of bounded active/closed records. Proxy-only filtering remains explicitly unavailable until a complete native observation source can preserve that distinction. This setting must be resolved before ordinary backend cutover; no filtered totals or per-application history are fabricated from the 1000-record window. Windows acceptance checks real TUN payload, positive UI rates/totals, a local display reset with monotonically preserved raw counters, recovered-session reads and the unchanged durable profile ledger.

## Control-only listener state

`CoreListenerSpec.withInbounds(false)` retains validated requested ports/TUN settings while the generated configuration omits mixed, DNS, TUN and private probe inbounds and their inbound-specific rules. The authenticated control API remains available. Requested settings still undergo normal validation, so an idle candidate does not approve an invalid future active configuration. Active probe/TUN/DNS accessors expose the effective listener state; Helper peer-PID checks and probe clients use the effective probe, preventing credentials from being sent to an inactive port owned by another process.

This is a prerequisite for preserving the application's distinction between backend connectivity and proxy enablement. It does not yet implement the application's main start/stop or profile-apply controller. Outbound groups and explicit API operations still exist in control-only mode; disabling inbounds does not promise that native health checks make no outbound requests. Tests keep the requested data ports occupied by owned fixtures, verify authenticated API selection/mode operations, and refuse scoped probe callbacks. Disposable Windows Helper acceptance additionally requires a SYSTEM-owned control-only process, no requested TUN address while it runs, untouched foreign listeners and confirmed process cleanup.

## Standalone proxy definitions

`CoreProxyDefinitions.validate` implements the existing per-proxy validation contract in Dart: one diagnostic string per input, with a malformed definition leaving its valid neighbors intact. The node parser is shared with full Clash imports, and protocol field checks are shared with the configuration builder. Parsing, bounds checks and diagnostic assembly run in isolates; batches are limited to 100,000 definitions and 16 MiB of encoded data. Error paths use input indexes and do not include credential values.

Standalone definitions can refer to a hostname, future dialer or a name another definition shares. They do not require a DNS plan or global group registry and perform no network or kernel calls. Empty names, required fields, protocol options, UUIDs, credentials and port ranges are checked. This is static field validation, not native protocol interoperability or validation of an entire configuration: DNS, graph references, duplicate tags and target-kernel initialization remain separate checks before activation. `SingBoxUiHandler.validateProxies` exposes this through the existing controller, enabling the input/editing path without the old kernel parser.

## Editable definitions and sharing

`CoreNodeDefinition` projects the committed typed node into an independent editable definition, preserving supported TLS, transport and detour fields. Lookup scans run in an isolate and the UI bridge rejects results after session or committed-configuration replacement. Selectors and absent names return no node definition.

`CoreShareLinkEncoder` keeps the existing one-string-per-input editing contract, including an empty string for a node without a faithful URI representation. Supported URI candidates are decoded and parsed again, then compared with the original typed definition before export. VMess's omitted cipher/alterId defaults normalize to auto/0; all other settings must survive. Detours, TCP-only overrides, extra WebSocket headers, unrepresented bandwidth options and malformed definitions cannot silently disappear into a share link. Unicode, delimiters and literal percent sequences in names and credentials are encoded once. Work and budgets stay off the UI isolate; neither editing nor sharing calls the running engine or changes its selection. These checks establish conversion behavior, not real remote-server interoperability.

## Runtime policy across listener replacement

The UI route coordinator submits reviewed configuration replacements and data-inbound enablement through the same desktop lifecycle owner. It serializes policy reads, preparation and submission with selection/mode mutations, then releases its queue while lifecycle activation is pending so a newer configuration or pause request can supersede that activation. Only an activation owned by this coordinator may reuse its last observed policy during a transition. Superseded preparation is not submitted; failed latest intent adopts the actual committed configuration, including lifecycle recovery. Settled listener requests do not restart the backend, and terminal close cancels pending preparation.

Recompilation of the same approved profile preserves observed manual selections, the synthetic global selection and actual mode, without pinning automatic URL-test groups. A different reviewed profile retains its own defaults and combines with the latest listener intent. `initialMode` and `globalSelection` are validated bootstrap settings; `withInbounds` preserves them. All three Clash modes are explicitly present in generated route rules, because the pinned engine registers modes from rules and the initial default: relying on a rule default alone makes switching back to rule unavailable after a global/direct bootstrap.

Pure-data profile projection and compilation run in isolates. No listener or configuration command becomes a process owner. Unit coverage includes preparation/selection ordering, pending-activation preemption, latest-profile/pause composition, committed-state adoption, failure and close. Native Windows acceptance separately requires `ui_listener_policy_retained`: controller pause/resume/restart through SYSTEM Helper, original-process exit witnesses, retained selections/mode, absent paused TUN address and real HTTP payloads after resumed/restarted sessions. This bridge remains separate from final ordinary-application construction and reviewed-source import integration.
